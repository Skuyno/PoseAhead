# PoseAhead — гайд по показу

Рабочий прототип · 13 октября 2026 · сценарий на 7–10 минут

## Что именно показываем

PoseAhead — платформа управления полнотелым аватаром по одной RGB-камере и исследования методов компенсации задержки. Готовы Python-пайплайн, интерфейс управления, передача поз в Unity, обработка записей, обученные predictor-модели и воспроизводимые эксперименты.

Главная мысль показа: система работает; на шумных validation-данных нейросетевой вариант уменьшает ошибку и дрожание. Доказанного выигрыша по задержке и окончательной приёмки ещё нет.

### Вступление, которое можно сказать

«Я разрабатываю методы управления виртуальным аватаром и исследую компромисс между задержкой, точностью позы и дрожанием. MeTRAbs восстанавливает 3D-позу по видео, Python обрабатывает её, Unity анимирует аватар. Мой исследовательский вклад — временная обработка, предсказание и честное сравнение методов».

### До встречи

- Не обновляйте Unity, CUDA и зависимости непосредственно перед показом.
- Основной сценарий — записи и тестовые позы: он не требует камеры или интернета.
- Live — дополнительная часть, только если DroidCam подключён и человек доступен.
- Откройте проект и гайд заранее; не запускайте одновременно несколько producer-сессий.
- При небольшом окне UI настройки и блок Unity прокручиваются отдельно; журнал остаётся снизу.

### Предварительная проверка

Откройте PowerShell в корне проекта:

```powershell
Set-Location E:/Progi/Coding/PoseAhead
.venv/Scripts/python.exe scripts/check_demo.py --load-models
```

Ожидается status: ready. Проверяются локальные записи, конфигурация и CPU-запуск моделей. Камера и UDP не включаются. Это не подтверждение приёма Unity или live-производительности.

## Основной показ без камеры

Отведите 3–4 минуты на движение аватара. Первый сценарий — самый надёжный запасной вариант.

1. Дважды нажмите StartPoseAhead.cmd в корне проекта. Либо выполните команду ниже. Появится окно PoseAhead.
2. В панели нажмите «Открыть проект Unity». Editor: F:/Unity/Editor/Unity.exe, версия 6000.3.23f1. Если проект уже открыт, используйте его окно, не запускайте второй Editor.
3. В Unity откройте Assets → PoseAhead → Scenes → PoseAheadDiagnostic 1. Нажмите Play и перейдите на вкладку Game. UDP-порт должен совпадать с панелью: по умолчанию 5005.
4. В «Сценарий показа» выберите «1 · Проверка аватара · без камеры», нажмите «Применить · без запуска», затем «Запустить». За 8 секунд пройдут тестовые позы: рука, нога, поворот, перемещение root, пропуск сустава, восстановление. Это синтетическая проверка, не оценка точности.
5. После завершения проверьте подтверждение Unity: сколько поз принято и применено. Растущий счётчик отправки сам по себе не доказывает приём.
6. Выберите сценарий «2 · CMU · Калман + 100 мс». Примените и запустите. Аватар воспроизведёт до 30 секунд упражнений CMU 13/29. Это реальная mocap-запись, не работа камеры.
7. По желанию повторите тот же клип со сценарием «3 · CMU · экспериментальная нейросеть». Он использует закреплённые модели и adaptive-конфигурацию с защитным переключением на Калман. Показываем интеграцию модели, а количественный эффект — по таблице результатов.

```powershell
.venv/Scripts/python.exe main.py gui
```

### Что говорить во время движения

«Сначала проверяю всю цепочку и восстановление после пропуска сустава. Затем воспроизвожу один и тот же клип через разные процессоры. Камера здесь выключена: демонстрация воспроизводима».

Не обещайте заметную разницу на чистой записи: нейросеть может иметь нулевой вклад. Сценарии не добавляют шум или искусственную задержку; визуальный повтор не заменяет эксперимент.

### Запасная запись детектора

Сценарий «4 · Сохранённый MeTRAbs · без камеры» проигрывает 60 сохранённых поз примерно за 2,5 секунды. Это совместимость с выходом детектора, не новый live-прогон. Записи не зацикливаются; повтор — новым запуском.

## Дополнительный live-показ

Отведите 1–2 минуты. Если камера недоступна, спокойно пропустите эту часть: основной показ уже завершён. Во время подготовки проекта камера автоматически не запускалась.

1. Подключите DroidCam привычным способом. Покажите человека целиком: голова, кисти и стопы должны помещаться в кадр; обеспечьте хорошее освещение.
2. В UI выберите источник «Камера · MeTRAbs». Индекс камеры на проверенной конфигурации этого компьютера — 0. Если состав устройств изменился, индекс может стать другим. Существующий backend — MSMF; не переключайте на DSHOW: ранее он приводил к native-сбою.
3. Для первого live-показа выберите «Без обработки · Raw» либо «Калман + экстраполяция», горизонт 100 мс. Файл камеры: configs/live/default.json. Длительность — 60 секунд. Сохранение исходных NPZ выключено; включайте его только при необходимости и согласии снимаемого человека.
4. Убедитесь, что Unity в Play, и нажмите «Запустить». Дождитесь загрузки MeTRAbs/CUDA, прогрева и состояния «Сессия работает». В процессе запуска смотрите журнал. Нулевая частота полных поз при идущих кадрах означает, что детектор не видит целую позу.
5. Поднимите руку, согните локоть, сделайте осторожный шаг в сторону и вперёд-назад. После завершения проверьте подтверждённый приём Unity и откройте результаты сессии.

### Как объяснить перемещение

Аватар не только двигает конечностями, но и меняет положение по оценке root. Это приближённое метрическое перемещение относительно камеры из монокулярной 3D-оценки. Без калибровки масштаба и камеры оно неточно; это не SLAM и не гарантированная глобальная траектория в помещении.

### Что означают показатели UI

- «Полных поз / с» — выход камеры, а не FPS рендера Unity.
- «Capture → send · p95» — 95-й процентиль времени от доступного кадра до завершения локальной отправки. Это не время от экспозиции камеры до картинки на экране.
- «Отправлено» — локальная отправка UDP; подтверждение приёма и применения проверяется отдельно по свежей телеметрии этой сессии.

Короткий показ не закрывает десятиминутную приёмку. 600 секунд нужны для отдельного повторного измерения стабильности, а не для каждого запуска на встрече.

## Результаты, которые можно защищать

Эксперименты CMU от 11 октября: три validation-клипа и три seed шума; клипы/seed имеют равный вес. Test-часть не оценивалась. Цифры ниже — повторная validation, не независимая итоговая проверка.

### Ошибка отображаемой позы и дрожание

| Шум, σ в мм | Калман: ошибка / jitter | Adaptive: ошибка / jitter |
| --- | --- | --- |
| 0 | 25,34 / 6,20 | 24,79 / 6,17 |
| 10 | 31,80 / 36,63 | 30,40 / 34,39 |
| 25 | 47,43 / 88,44 | 43,42 / 80,04 |
| 50 | 77,02 / 175,76 | 68,73 / 156,99 |

Источник: selection.json панели cmu_adaptive_confirmation_gaussian_20261011.

Ошибка — в миллиметрах; jitter — средняя ошибка ускорения относительно эталона, в м/с². В этой таблице меньше — лучше. σ — стандартное отклонение искусственного гауссовского шума координат, не точность камеры. Jitter здесь — ошибка второй производной, не субъективная оценка плавности.

«При σ = 25 мм средняя ошибка уменьшилась примерно на 8,5%, дрожание — на 9,5%. Но доказательства снижения задержки пока нет». Не заменяйте этим выводом приёмку live.

### Исправленная проблема редких пропусков

При σ = 25 мм и вероятности пропуска каждого сустава 0,2%: Калман — 48,16 мм; старый adaptive — 56,37 мм; исправленный — 47,24 мм. При частичной потере позы теперь сохраняются фильтры доступных суставов, а нейросетевая история сбрасывается. Старый отрицательный результат сохранён.

При частых пропусках 5%/15% и потере tracking оба метода не проходят полный порог покрытия SPEC. Общего победителя нет. Не показывайте уменьшение ошибки только на оставшихся кадрах как успех всего алгоритма.

### Сохранённый десятиминутный live-прогон, 5 октября

Получено 18,01 полных поз/с; p95 capture → send — 98,43 мс. Отправлено, принято и применено одинаково: 10 809 поз. Доставка подтверждена, но цели ≥25 поз/с и p95 ≤50 мс не достигнуты. Это старый прогон, не результат сегодняшнего показа.

Сводка и хеши источников: outputs/demo_20261013_verified/results.md и evidence.json. Подробности: docs/adaptive_confirmation.md.

## Если что-то пошло не так

### Аватар не двигается

Проверьте Play, Game, нужную сцену и одинаковый порт. Начните со сценария 1. Нет приёма при идущей отправке — смотрите Unity Console и журнал worker. Не отключайте VPN/firewall наугад: связь локальная, через 127.0.0.1.

### Долго висит загрузка или нужна остановка

Нажмите «Остановить», следите за журналом. Через 5 секунд станет доступно «Принудительно завершить…»: оно завершает только worker этой сессии. Несохранённая запись может потеряться. Не завершайте все Python/Unity-процессы через диспетчер задач.

### Сценарий 3 недоступен

Нужны четыре checkpoint в outputs и adaptive_kalman_recovery_pilot.json. Проверьте preflight, но не скачивайте и не переобучайте модели на встрече. Покажите сценарий 2 и сохранённые результаты.

### Вопросы научрука — короткие ответы

- «Своя нейросеть обучена?» — Да: predictor на 33/66/100/150 мс; шумная модель — на 100 мс. Они прогнозируют движение, не детектируют человека.
- «Что здесь ваше?» — Временная обработка, предсказание, adaptive-логика, интеграция и эксперименты. MeTRAbs — готовый backend.
- «Задержку уменьшили?» — Ещё не доказано. Есть улучшение ошибки/дрожания в некоторых шумных validation-условиях.
- «Какой датасет?» — CMU mocap, 17 суставов; не RGB-эталон камеры. Human3.6M в эти результаты не входит.
- «Почему нет разницы с нейросетью?» — Защита может отключить её вклад. На сохранённом MeTRAbs smoke все 60 выходов были Kalman-only, не neural-успехом.

### Как завершить встречу

«Прототип и воспроизводимые проверки готовы. Далее нужны более независимая проверка модели, подтверждение выигрыша по задержке и повторная live-приёмка. Данные test пока не использовались для выбора настроек».

## Техническая шпаргалка

Все команды запускаются из E:/Progi/Coding/PoseAhead. Интернет для штатного локального показа не требуется; уже установленные зависимости и файлы outputs должны оставаться на этом компьютере.

### Если UI не открывается

Запустите через python.exe, чтобы увидеть ошибку в консоли:

```powershell
.venv/Scripts/python.exe main.py gui
```

### Если нужен запасной запуск без UI

В Unity сначала нажмите Play. Затем отправьте тестовые движения:

```powershell
.venv/Scripts/python.exe scripts/replay_unity.py --diagnostic
```

Пока этот процесс работает, не запускайте producer из UI. Для другого порта добавьте --port с тем же номером, что в Unity.

### Обновить сводку перед следующей встречей

```powershell
.venv/Scripts/python.exe scripts/prepare_demo.py --output outputs/demo_NEW
```

Укажите новый каталог. Скрипт проверит девять batch-наборов, воспроизведёт сохранённый выбор из закреплённых артефактов и запишет results.md/evidence.json. Он не включает камеру, не отправляет UDP, не обучает модель и не перезаписывает старые эксперименты.

### Где сохраняются результаты показа

- Для каждого UI-запуска создаётся отдельный outputs/ui_…: request.json, processor.json, worker.log, report.json и run_report.json.
- observations.npz появляется только при явно включённом сохранении камеры и полученных наблюдениях.
- Исходные CMU/MeTRAbs NPZ не меняются. Старые результаты и checkpoint не очищайте перед показом.
